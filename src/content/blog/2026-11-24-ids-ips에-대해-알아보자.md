# IDS(Intrusion Detection System)
침입 탐지 시스템(IDS)은 네트워크 트래픽과 디바이스에서 알려진 악의적 활동, 의심스러운 활동 또는 보안 정책 위반이 있는지 모니터링하는 네트워크 보안 도구다. 탐지하고 알리는 것까지만 하고, 차단은 하지 않는다.
 
## 동작원리
패킷 복사본(SPAN, TAP)이나 호스트 로그를 수집 → 분석 → 위협이면 경고를 보내고 SIEM에 기록한다.
 
탐지 방식
- **시그니처 기반**: 알려진 공격 패턴 DB와 비교한다. 알려진 공격은 정확히 잡지만 신규 공격(제로데이)은 못 잡는다.
- **이상 징후 기반**: 정상 트래픽 기준선을 만들고 벗어나면 탐지한다. 신규 공격도 잡지만 오탐이 많다.
- **평판 기반**: 악성으로 알려진 IP·도메인을 탐지한다.
- **상태 기반 프로토콜 분석**: 짧은 시간에 TCP 연결 요청이 과도한 것처럼 프로토콜이 비정상 동작하면 탐지한다.

## 유형
| 유형 | 감시 대상 | 특징 |
|---|---|---|
| NIDS | 네트워크 전체 트래픽 | 방화벽 근처, 대역 외 배치라 트래픽 지연 없음 |
| HIDS | 설치된 호스트 1대 | OS 파일 스냅샷을 비교해 변경 감지 |
| PIDS | HTTP/HTTPS 프로토콜 | 웹 서버에 배치 |
| APIDS | 애플리케이션 계층 프로토콜 | 웹 서버-DB 사이에서 SQL 인젝션 탐지 |
 
대표 오픈소스: Snort, Suricata, Zeek(NIDS) / OSSEC, Wazuh(HIDS)

## 활용방법
- **위협 경고 자동화**: 사람이 일일이 로그를 보지 않아도 IDS가 위협을 탐지해서 알려준다.
- **SIEM 연동**: IDS 경고를 방화벽, 엔드포인트 등 다른 보안 도구 데이터와 합쳐서 보고, 오탐을 걸러내고 대응 우선순위를 정한다.
- **규정 준수**: PCI-DSS 같은 규정은 침입 탐지 수단을 요구한다. IDS로 이 요건을 충족한다.
- **내부 확산 탐지**: HIDS로 감염된 장비에서 퍼져 나가는 랜섬웨어 같은 활동을 탐지한다.

### IDS 회피 기법
공격자는 IDS를 피하기 위해 다음 방법을 쓴다.
- **DDoS 미끼**: 대량 트래픽으로 IDS를 과부하시켜서 진짜 공격을 놓치게 만든다.
- **IP 스푸핑**: 출발지 IP를 위조해서 추적을 어렵게 한다.
- **패킷 단편화 (Fragmentation)**: 공격 페이로드를 여러 조각으로 나눠서 시그니처 매칭을 피한다.
- **암호화**: TLS 등으로 페이로드를 암호화하면 복호화 없이는 내용을 검사할 수 없다.
- **경고 폭탄**: 일부러 대량의 경고를 발생시켜 보안팀의 주의를 분산시킨다.

# IPS(Intrusion Prevention System)
침입 방지 시스템(IPS)은 네트워크 트래픽의 잠재적 위협을 모니터링하고, 보안팀에 경고를 보내거나 위험한 연결을 종료하며, 악성 콘텐츠를 제거하거나 다른 보안 장치를 작동시키는 등의 조치를 자동으로 수행한다.

IDS는 탐지까지 하는데 IPS는 더 나아가서 차단이나 보안조치를 수행한다.

## 동작원리
IPS의 탐지 기능은 IDS에서 발전한 것이고, 여기에 **자동 차단** 기능이 붙은 구조다.

### 인라인(Inline) 배치
IPS는 실시간으로 차단해야 하기 때문에 트래픽 경로 한가운데에 **인라인**으로 배치된다. 모든 트래픽은 목적지에 닿기 전에 반드시 IPS를 통과한다. 복사본만 보는 IDS와 가장 큰 구조적 차이다.

![](/assets/images/posts/2026-11-24-ids-ips에-대해-알아보자/ips-mww6np9h.svg)

### 탐지 방식
IDS의 탐지 방식(시그니처, 이상 징후, 평판, 상태 기반 프로토콜 분석)을 그대로 쓰고, 하나가 더 있다.

- **정책 기반 탐지 (Policy-based)**: 보안팀이 정한 규칙(예: 특정 호스트만 특정 서버에 접근 가능)을 위반하면 차단한다. 조직에 맞게 세밀하게 통제할 수 있지만, 정책을 처음 만드는 데 노력이 많이 든다.

### 탐지 후 대응 조치
- **악성 트래픽 차단**: 세션 종료, 출발지 IP 차단, 대상으로 가는 트래픽 전면 차단. 일부 IPS는 트래픽을 허니팟으로 우회시킨다.
- **악성 콘텐츠 제거**: 연결은 유지하고 악성 패킷이나 이메일 첨부 파일 같은 위험 요소만 제거한다.
- **다른 보안 장치 연동**: 방화벽 규칙을 갱신하거나 라우터 설정을 바꾸도록 트리거한다.
- **보안 정책 강제**: 예를 들어 DB 밖으로 민감 정보가 전송되는 것을 막는다.
- **기록 및 보고**: 이벤트를 기록하고 SIEM을 통해 SOC에 보고한다.

## 유형
| 유형 | 감시 대상 | 특징 |
|---|---|---|
| **NIPS** (Network-based) | 네트워크 인바운드·아웃바운드 패킷 | 주로 방화벽 뒤에 배치. 핵심 자산 주변 내부망에 두기도 한다. |
| **HIPS** (Host-based) | 설치된 엔드포인트 1대의 트래픽 | 보통 NIPS와 같이 쓴다. 내부에서 퍼지는 랜섬웨어 같은 활동을 막는다. |
| **NBA** (Network Behavior Analysis) | 세션 수준 정보 (IP, 포트, 패킷 수 등) | 패킷 내용보다 흐름을 본다. 이상 징후 기반으로 DDoS 트래픽 급증, C&C 서버 통신을 탐지한다. |
| **WIPS** (Wireless) | 무선 네트워크 프로토콜 | 미승인 기기 접속, 잘못 설정된 AP(Rogue AP), 중간자 공격(MITM)을 탐지하고 연결을 끊는다. |

Snort와 Suricata는 인라인 모드로 설정하면 IPS로 동작한다.

## 활용방법
- **방화벽 다음의 두 번째 방어선**: 방화벽은 IP·포트 규칙으로만 거른다. 허용된 포트(예: 80/443)로 들어오는 공격은 방화벽을 통과하는데, IPS가 패킷 내용을 보고 이걸 막는다.
- **SIEM 연동**: IPS 알림을 다른 보안 도구 정보와 같이 보면서 오탐을 걸러내고 차단 결과를 확인한다.
- **SOC 업무 부담 감소**: 단순한 위협은 IPS가 자동으로 막으니 보안팀은 복잡한 위협 분석에 집중한다.
- **규정 준수**: PCI-DSS 같은 침입 탐지 요구 사항을 충족한다.
- **배포 형태**: 엔드포인트 소프트웨어, 전용 하드웨어, 클라우드 서비스 중에서 고른다. 차세대 방화벽(NGFW)에는 IPS 기능이 내장된 경우가 많다.

# 장단점
## IDS
**장점**
- 대역 외에 배치되므로 장애가 나도 서비스 트래픽에 영향이 없고, 지연도 없다.
- 시그니처 기반으로 알려진 공격을 정확히 탐지한다.
- 이상 징후 기반으로 제로데이 같은 신규 공격도 탐지한다.
- SIEM과 연계해서 네트워크 가시성을 높인다.

**단점**
- 스스로 차단하지 못한다. 경고를 받은 사람이 대응하기 전까지 공격은 계속 진행된다.
- 시그니처 기반은 DB 업데이트에 의존하고, 신규 공격에 우회당한다.
- 이상 징후 기반은 오탐이 많고, 경고가 많아서 진짜 중요한 경고를 놓칠 수 있다.
- 패킷 단편화, 암호화, IP 스푸핑, 과부하 공격으로 회피당한다.

## IPS
**장점**
- 위협을 자동으로 즉시 차단하므로 대응 속도가 빠르다.
- 이상 징후 기반 탐지로 시그니처가 없는 공격에도 대응한다.
- 정책 기반 탐지로 조직 맞춤형 통제가 가능하다.
- 단순 위협 처리를 자동화해서 SOC 부담을 줄인다.

**단점**
- IDS의 오탐은 경고 하나로 끝나지만 IPS의 오탐은 차단을 하기 때문에 서비스 장애로 커질 수 있다.
- 인라인 배치라 모든 트래픽을 검사하는 만큼 지연이 생기고, IPS의 처리 성능이 곧 네트워크 처리 성능의 상한이 된다.
- IPS 장비가 죽으면 트래픽 경로가 끊긴다(단일 장애 지점). 그래서 장애 시 트래픽을 그냥 통과시키는 fail-open이나, 전부 막는 fail-closed 중 하나를 정해야 한다.
- 시그니처 DB 갱신, 정책 수립에 지속적인 비용과 노력이 든다.

# 차이점
| 구분 | IDS | IPS |
|---|---|---|
| 기능 | 탐지, 경고 | 탐지 + 차단 |
| 배치 | 대역 외(복사본 분석) | 인라인 |
| 대응 | 사람이 판단 | 자동 |
| 오탐 결과 | 불필요한 경고 | 정상 트래픽 차단 |
 
### 방화벽과의 관계
방화벽은 IP·포트 규칙으로 거르고, IDS는 통과한 트래픽을 감시하고, IPS는 통과한 트래픽의 내용까지 보고 막는다.
 
### EDR, XDR과의 차이
| 구분 | 보는 범위 | 대응 |
|---|---|---|
| IDS | 네트워크 | 경고 |
| IPS | 네트워크 | 차단 |
| EDR | 엔드포인트 행위(프로세스, 파일, 연결) | 프로세스 종료, 호스트 격리 |
| XDR | 엔드포인트 + 네트워크 + 이메일 + 클라우드 | 계층 통합 자동 대응 |
 
SIEM은 로그 수집·상관분석이 중심이고, XDR은 대응 자동화까지 포함한다. 요즘은 IDS/IPS를 XDR에 들어가는 네트워크 데이터 소스 중 하나로 보는 흐름이다.
 
**Wazuh**: OSSEC 기반 오픈소스로, 지금은 XDR + SIEM 통합 플랫폼이다. Active Response를 켜면 조건 충족 시 출발지를 차단해서 HIPS처럼 동작한다.
